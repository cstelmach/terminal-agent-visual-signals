### P2: Symlink-loop root resolution bypasses the private CLI failure boundary

- Situation: `src/core/portable_helper.py:37-47` resolves `TAVS_TEST_ROOT`, marker and runtime

- Behavior: `Path.resolve()` can raise `RuntimeError` for a symlink loop. The exception handler

- Impact: a malformed test-root or contained marker/runtime path crashes with a traceback
  instead of returning code 1, empty stdout and the fixed unavailable message. The exception
  message includes the resolved private path, violating the helper's private failure boundary.
- Source verification: the locally installed Command Line Tools Python 3.9 standard library
  at `/Library/Developer/CommandLineTools/Library/Frameworks/Python3.framework/Versions/3.9/lib/python3.9/pathlib.py:337-344`
  raises `RuntimeError("Symlink loop from %r" % newpath)` even for non-strict resolution.
  `README.md:1087` requires Python 3 without excluding this runtime. This is established from
  source, not reproduced by execution. The precise exception category is version dependent.
- Small fix: convert root-resolution `RuntimeError` to the existing unavailable category, or
  include this known path-resolution category in the helper's private exception boundary.
